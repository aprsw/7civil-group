# سامانه اتوماسیون اداری گروه متحد 7

سیستم کامل اتوماسیون نامه‌های اداری گروه داروسازی **گروه متحد 7** — پیاده‌سازی
واقعی و آمادهٔ production از دیزاینِ صادرشده از Claude Design.

- **بک‌اند:** PHP خالص (بدون Laravel/فریم‌ورک)، معماری **MVC-R**، **PSR-4**،
  namespace‌محور، رعایت **SOLID** و **Design Pattern**‌ها، خروجی **JSON API**،
  تقویم **جلالی** (نوشته‌شده از صفر).
- **فرانت‌اند:** **Vue 3 + TailwindCSS**، کاملاً **CSR**، فونت **ایران‌سنس** (self-host، بدون CDN).
- **پایگاه‌داده:** پیش‌فرض **SQLite** (بدون تنظیمات اجرا می‌شود)؛ **MySQL** هم پشتیبانی می‌شود.

> طرح اصلی (پروتوتایپ و گفتگوها) در پوشه‌های `project/` و `chats/` نگهداری شده است.

## اجرا در ۴ گام
نیازمندی‌ها: PHP ≥ 8.1 (با `pdo_sqlite`) و Node ≥ 18.

```bash
# ۱) بک‌اند (API روی پورت 8000)
cd backend
php bin/console install          # ساخت جداول + دادهٔ نمونه
php -S 127.0.0.1:8000 -t public

# ۲) فرانت‌اند (CSR روی پورت 5173)
cd frontend
npm install
npm run dev                      # /api خودکار به بک‌اند پراکسی می‌شود
```
مرورگر: <http://127.0.0.1:5173>

### اجرا روی MySQL (اختیاری)
پیش‌فرض SQLite است. برای MySQL، پایگاه‌داده را بسازید و متغیرهای محیطی را تنظیم کنید:
```bash
mysql -e "CREATE DATABASE civil7_automation CHARACTER SET utf8mb4;"
cd backend
export DB_DRIVER=mysql DB_HOST=127.0.0.1 DB_PORT=3306 \
       DB_NAME=civil7_automation DB_USER=root DB_PASS=yourpass
php bin/console install       # همان جداول روی MySQL ساخته می‌شود
php -S 127.0.0.1:8000 -t public
```
> اسکیمای یکسان روی هر دو موتور ساخته می‌شود (تفاوت فقط در بند کلید اصلیِ
> auto-increment است که خودکار سوییچ می‌شود).

## قابلیت‌ها (production)

### به‌روزرسانی نسخهٔ ۸ (اصلاحات دبیرخانه و صندوق نامه)
- **جدایی دبیرخانه از صندوق نامه**: نامه‌هایی که از دبیرخانه ثبت می‌شوند (وارده/صادره) دیگر در
  «نامه‌های ارسالیِ» کاربرِ ثبت‌کننده نمایش داده نمی‌شوند؛ فقط در صفحهٔ دبیرخانه هستند
  (نامهٔ واردهٔ ارجاع‌شده همچنان به صندوق «دریافتیِ» گیرندهٔ داخلی می‌رود).
- **شمارهٔ دستی در دبیرخانه**: شمارهٔ نامه را خودِ کاربر وارد می‌کند؛ سامانه فقط **تکراری‌نبودن**
  آن را کنترل می‌کند (ارقام فارسی/لاتین یکسان در نظر گرفته می‌شوند)، **آخرین شمارهٔ ثبت‌شده** را
  نمایش می‌دهد و «شمارهٔ بعدی» را پیشنهاد می‌کند. نامه‌های عادی مثل قبل خودکار شماره می‌گیرند.
  (`GET /api/secretariat/last-number`, `GET /api/secretariat/check-number?number=…`)
- **بخش‌بندی دبیرخانه فقط توسط ادمین**: ایجاد/ویرایش/حذف بخش‌ها (پوشه‌ها) نیازمند مجوز جدید
  `secretariat.manage` (یا `roles.manage`) است؛ کاربران دبیرخانه فقط می‌توانند نامه را در بخش‌های
  موجود قرار دهند. این مجوز از «دسترسی کاربران» قابل واگذاری است.
- **بخش «خوانده‌نشده» در صندوق نامه**: زیرِ «دریافتی» (نامه‌هایی که خودتان باز نکرده‌اید) و زیرِ
  «ارسالی» (نامه‌هایی که هنوز هیچ گیرنده‌ای باز نکرده) با شمارنده؛ `GET /api/letters?box=in|out&read=unread`.

### به‌روزرسانی نسخهٔ ۷ (صندوق نامه و موارد جدید)
- **صندوق نامه** (جایگزین «کارتابل من»): در منوی اصلی سه بخش **نامه‌های دریافتی / ارسالی /
  منتظر اقدام**؛ در هر بخش زیرفیلترِ **نوع** (همه/اقدام/اطلاع/امضا/پاسخ/پیگیری).
- **فولدرهای شخصی**: هر کاربر فولدر می‌سازد (به‌همراه **بایگانی**) و نامه‌ها را (حتی
  **چندتایی**) به فولدر منتقل می‌کند؛ بایگانی دیگر خودکار پُر نمی‌شود.
- **دیده/نادیده** با رنگ و آیکون پاکت (باز/بسته)؛ نامهٔ خوانده‌شده از «منتظر اقدام» خارج و در «دریافتی» می‌ماند.
- **نوع اقدام** و **رونوشت (CC)** در نگارش نامه؛ **درج جدول** در متن نامه؛ ذخیرهٔ متن به‌صورت HTML (جدول/قلم/رنگ حفظ می‌شود).
- **امضای داینامیک**: تنظیم‌کننده و هر تأییدکنندهٔ گردش‌کار (سمت + نام) در نامه و چاپ؛ بدون بوردر، بزرگ‌تر، سمت چپ.
- **چارت هرمی گیرندگان**: سطح ۱ به همه؛ هر سطح به هم‌سطحی‌ها، و در واحد خود به یک سطح بالاتر و همهٔ سطوح پایین‌تر.
- **تقویم شمسی** روی فیلدهای تاریخ (تایپ و انتخاب، ارقام فارسی).
- **رمز عبور** قابل تغییر توسط هر کاربر در پروفایل.
- **داشبورد**: کارت‌های وارده/صادره/مشاهده‌نشده/منتظر اقدام + **رویدادهای امروز و این هفته**.
- **اعلان‌ها**: نامه‌های دریافتیِ خوانده‌نشده (+ نمای «همه»).
- **گردش کارها**: تعریف **چندین** گردش کار + **بررسی چارت** (هشدار برای نقش بدون مجوز تأیید و…).
- **وضعیت نامه**: عادی → «ارسال شد»/«پیش‌نویس»؛ گردش‌کاری → **عنوان مرحلهٔ جاری** و نقشِ مرحلهٔ بعد.
- **ذخیره در دسکتاپ**: خروجی نامه به‌صورت فایل HTML مستقل.

### پایه
- **ورود** با JWT و منوی کاربری (خروج/پروفایل) در هدر؛ **زنگ اعلان‌ها** واقعی و کارا.
- **داشبورد** با آمار زنده، آخرین نامه‌ها و پیشرفت گردش کارها.
- **کارتابل** (کارتابل من/وارده/صادره/پیش‌نویس). «کارتابل من» بر اساس نوعِ ارجاع
  **گروه‌بندی** می‌شود (گردش‌کار/گیرندهٔ مستقیم/جهت اقدام/جهت اطلاع/جهت استحضار).
- **نگارش نامه** (ادیتور واقعی):
  - **فرستنده** = کاربر واردشده (خودکار)؛ قلم/اندازهٔ px/رنگ متن و پس‌زمینه.
  - **چند گیرنده**: افزودن **چند شخص و/یا چند واحد** به‌صورت چیپ، یا **گیرندهٔ خارج‌سازمانی**.
  - **نوع نامه**: **عادی** (تحویل مستقیم) یا **گردش‌کاری** (استپرِ تأیید/امضا).
  - **دامنه**، **محرمانگی** (عادی/محرمانه/سری)، **اولویت**.
  - **تا ۱۰ پیوست** از انواع Word/Excel/PDF/PowerPoint/متن/تصویر — دانلودِ تک‌تک.
  - **تصویر امضا** (خودِ کاربر بارگذاری می‌کند) در پای نامه درج می‌شود.
  - **ذخیرهٔ پیش‌نویس** و ادامهٔ ویرایش؛ انتخاب اندازهٔ **A4/A5** + چاپ.
- **ارجاع نامه (ارجاع)**: هدایتِ نامه به افراد/واحدها با نوعِ **جهت اقدام/اطلاع/استحضار** و یادداشت.
- **رسید خواندن**: مشخص‌بودنِ خوانده‌شدن/نشدن نامه به تفکیک هر گیرنده.
- **فراخوان (Recall)**: فرستنده تا پیش از خوانده‌شدن می‌تواند نامه را حذف/فراخوان کند.
- **پاسخ به نامه** و **زنجیره/درخت‌وارهٔ نامه**؛ تبِ **رویدادهای نامه** (ثبت/مشاهده/ارجاع/گردش).
- **قالب‌ساز**، **کنترل دسترسی سطر‌به‌سطر**: نامهٔ **سری** فقط فرستنده و گیرندگان، نامهٔ **محرمانه**
  به‌علاوهٔ مدیر عامل.
- **کاربران، نقش و واحد**: CRUD کامل، **فعال/غیرفعال**، فهرست **آنلاین‌ها**، تصویر پروفایل و امضا.
- **پروفایل من**: ویرایش اطلاعات تماس، تصویر و امضا توسط هر کاربر.
- **واحدها**: **CRUD** برای مدیر ارشد (`departments.manage`)، فهرست برای مدیران.
- **نقش‌ها و دسترسی‌ها**: تعریف/ویرایش/حذف نقش و سطح، و **اختصاص مجوزها** با
  چک‌باکس (`roles.manage`) — مبنای دادن/گرفتنِ دسترسی به کاربران.
- **مجوزهای مکاتبه بین واحدها** (`messaging.manage`): مدیر ارشد تعیین می‌کند هر
  واحد به کدام واحدها اجازهٔ ارسال نامه دارد؛ در نبودِ قاعدهٔ سفارشی، سلسله‌مراتب
  پیش‌فرض اعمال می‌شود (مدیرعامل هرگز محدود نمی‌شود).
- **نوع نامه**: **عادی** بدون تأیید/امضا مستقیم تحویل می‌شود؛ **گردش‌کاری** روند
  تأیید را طی می‌کند.
- **داشبورد**: کارت‌های آمار **کلیک‌پذیر** (به کارتابل/بایگانیِ متناظر)، **رویدادهای
  امروز**، و **چیدمانِ شخصی‌سازی‌شونده** که در مرورگرِ هر کاربر ذخیره می‌شود.
- **چاپ نامه** (عادی یا گردش‌کاری) دقیقاً مطابق نمایش و اندازهٔ کاغذ (A4/A5).
- **گردش کارها**: طراح گردش کار (فقط مدیران).
- **گفتگو (چت)**: پیام و **ارسال فایل** بین همکاران، **گروه** (ایجاد/حذف توسط کاربر ارشد)،
  حذفِ خودکار پیام‌ها و فایل‌های قدیمی‌تر از **۲ ماه**؛ دسترسی با `chat.use` (قابل واگذاری/سلب).
- **کارتابل خوانده‌محور**: نامهٔ خوانده‌نشده در «کارتابل من»؛ پس از مشاهده به «وارده» می‌رود.
- **انتخابگر تاریخ جلالی**: روی فیلدهای تاریخ، تقویم شمسی باز می‌شود (هم تایپ، هم انتخاب).
- **ارجاعات**: جهت اقدام / اطلاع / استحضار / مشورت / پیگیری.
- **رویدادهای سازمان**: تقویم رویدادها برای همه؛ **ایجاد/ویرایش/حذف** با دسترسی `events.manage`؛
  **رویدادهای امروز** در داشبورد.
- **تنظیمات (مدیر عامل)**: **الگوی شماره‌گذاری نامه** قابل‌پیکربندی
  (`{seq}`/`{yy}`/`{yyyy}`/`{mm}`/`{dept}`) با پیش‌نمایش زنده.

## معماری بک‌اند — MVC-R
```
backend/
├── public/index.php        ← Front Controller
├── bootstrap/app.php        ← Composition Root (DI)
├── routes/api.php           ← جدول مسیرها
├── bin/console              ← CLI: migrate | seed | install
└── src/
    ├── Core/                ← Autoloader(PSR-4) · Container(DI) · Router · Http · Application
    ├── Domain/              ← Model: Entities · Enums · Repository Interfaces
    ├── Infrastructure/      ← Database(PDO/Migrator/Seeder) · Repository (PDO impls)
    ├── Services/            ← Auth · Letter · LetterAccess(visibility) · Workflow · User · Dashboard · AccessControl
    ├── Security/            ← JWT (HS256 دست‌ساز) · BcryptHasher
    ├── View/                ← Transformerها (JSON + تاریخ جلالی)  ← «V» در MVC-R
    └── Support/Jalali.php   ← مبدل میلادی↔جلالی (بدون کتابخانه)
```
**الگوها:** Front Controller، DI Container، Repository، Factory (اتصال DB)،
Chain of Responsibility (میان‌افزار)، Transformer/DTO، Value Object، Service Layer.
**SOLID:** رابط‌های کوچک Repository، وابستگی به abstraction از طریق Container (DIP)،
هر کلاس یک مسئولیت (مثلاً `AccessControl` مجوّزها، `LetterAccess` رؤیت‌پذیری نامه).

### RBAC و واحدها
هر **نقش** یک **سطح** (۱ بالاترین) و مجموعه‌ای از **مجوز** دارد
(`Domain/Enums/Permission`). هر **کاربر** به یک نقش و یک واحد تعلق دارد.
مجوّزدهی متمرکز در `Services/AccessControl` و رؤیت‌پذیری نامه‌ها در `Services/LetterAccess`.

## نقاط انتهایی API (خلاصه)
| متد | مسیر | توضیح |
|---|---|---|
| POST | `/api/auth/login` · GET `/api/auth/me` | ورود / کاربر جاری |
| GET | `/api/dashboard` · `/api/notifications` | داشبورد / اعلان‌ها |
| GET | `/api/meta/compose` | گزینه‌های فرم نگارش (گیرندگان، واحدها، گردش‌کارها، enumها) |
| GET | `/api/letters?direction=in\|out\|draft` | فهرست (فیلترشده بر اساس دسترسی) |
| GET | `/api/letters/{id}` | نمایش نامه + زنجیره (`thread`) |
| POST | `/api/letters` | ثبت/ارسال (و پاسخ با `reply_to_id`) |
| POST | `/api/letters/{id}/approve` · `/reject` | تأیید/عدم‌تأیید |
| GET | `/api/letters/{id}/download` | دانلود پیوست |
| POST | `/api/attachments` | آپلود پیوست (multipart) |
| GET/POST/PUT/DELETE | `/api/users[/{id}]` | مدیریت کارکنان (`users.manage`) |
| GET/POST/PUT/DELETE | `/api/templates[/{id}]` | قالب‌ساز (`templates.manage`) |
| GET | `/api/departments` | واحدها (فقط مدیر عامل) |
| GET/POST/PUT | `/api/workflows[/{id}]` | گردش کارها (`workflow.manage`) |

پاسخ‌ها در پوشش `{ success, message, data }` و تاریخ‌ها جلالی با ارقام فارسی هستند.
